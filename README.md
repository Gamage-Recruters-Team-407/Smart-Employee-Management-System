# Smart Employee Management System

A MERN-style employee management application for employee records, document uploads, search/filter workflows, and basic HR modules such as attendance, leave, payroll, and performance.

## Tech Stack

- Frontend: React, Vite, Tailwind CSS, Axios, Lucide React
- Backend: Node.js, Express, MongoDB, Mongoose, Multer
- Storage: uploaded employee documents are stored in `backend/uploads`

## Prerequisites

- Node.js 18+
- MongoDB connection string

## Environment Variables

Create `backend/.env`:

```env
MONGO_URI=mongodb+srv://<user>:<password>@<cluster>/<database>
PORT=5000
```

The frontend currently calls the API at `http://localhost:5000/api` from `frontend/src/services/api.js`.

## Run Backend

```bash
cd backend
npm install
npm run dev
```

Backend runs on `http://localhost:5000`.

## Employee Demo Data And Tests

Seed demo employees only:

```bash
cd backend
npm run seed:employees
```

Run employee-only API tests:

```bash
cd backend
npm run test:employees
```

## Run Frontend

```bash
cd frontend
npm install
npm run dev
```

Frontend runs on the Vite URL shown in the terminal, usually `http://localhost:5173`.

## API Endpoints

### Employees

- `GET /api/employees` - list employees
- `GET /api/employees?search=&department=&designation=` - search by name/email and filter by department/designation
- `GET /api/employees/:id` - get one employee
- `POST /api/employees` - create employee
- `PUT /api/employees/:id` - update employee
- `DELETE /api/employees/:id` - delete employee

### Documents

- `POST /api/employees/:id/documents` - upload one document using multipart field `document`
- `DELETE /api/employees/:id/documents/:docId` - delete one employee document

Allowed upload types: PDF, JPG, PNG. Maximum file size: 5 MB.

## Manual Testing Checklist

- Create an employee, then create another employee with the same email and confirm the UI shows the backend `409` duplicate email error.
- Open Documents for an employee, upload a valid PDF/JPG/PNG, and confirm the file appears in the list.
- Try uploading an invalid file type or a file over 5 MB and confirm the UI shows an error.
- Edit an employee and confirm the table refreshes with the updated values.
- Delete an employee and confirm the row is removed after confirmation.
- Combine search, department, and designation filters and confirm the table updates after the debounce.

## Notes

- Employee IDs are generated by the backend and are not editable.
- The employee document list is stored on the employee record in MongoDB, while the files are stored on disk.
